# Admin CSV bulk product import

The import is available under Admin → Products → Bulk Product Import. It requires an authenticated admin and same-origin POST. It is create-only: an existing product slug or SKU is skipped and never overwritten.

## Current workflow and data

Download the authenticated template from `/api/admin/products/import/template`, select the CSV, optionally select a numbered photo ZIP, run preview, then confirm. The browser displays upload percentage and an indeterminate server-processing state; the synchronous server work does not currently report per-product progress. CSV supports up to 500 products and 2 MB. Required fields are `name`, `slug`, `category`, `price`, and `stock`; category accepts an active category name, slug, or ID. Optional JSON columns carry the existing color options, size options, fixed length (`meterOptions`) data, specifications, and universal variant records. Use the same JSON object shapes accepted by the existing product and variant admin APIs. Other columns map to the existing Product model, including pricing mode, per-meter price, stock, product details, visibility flags, shipping/enquiry settings, and SEO fields. Variant prices and stock must be supplied by an authorized data owner; the importer does not infer them.

The authenticated template and product export share one column definition. The template includes product ID (informational only), name, SKU, slug, category/subcategory, descriptions, pricing, stock, photo numbers, image URLs, JSON options/variants, visibility flags, storefront settings, and SEO. Product export is a read-only, UTF-8-with-BOM CSV stream paged in batches of 100. It can export all products from the import page, or the current search/category/subcategory/status filters from the Products list. All exported cells are CSV-quoted and values that could begin spreadsheet formulas are prefixed defensively. Exporting a product does not make an existing SKU eligible for update: create-only imports still skip existing SKUs/slugs.

`Image URLs` accepts comma-separated public HTTPS URLs; legacy `mainImage` and comma-separated `additionalImages` columns remain supported. The “Automatically Download Images” option defaults on. When on, supported images are validated and stored locally in persistent media storage. When off, external HTTPS URLs are retained as remote product image links without a server-side download; the source must continue to serve them. Existing stored media paths from the export are validated and reused. `photoNumbers` is a comma-separated list of exact numeric file stems. A row with `1281, 1282, 1286` matches files such as `1281.jpg`, `folder/1282.png`, and `1286.webp`; it does not confuse `1281` with `12810`. Nested ZIP folders are supported. Duplicate numbered stems are ambiguous and rejected. Supported formats are JPG/JPEG, PNG, and WebP. Numbered ZIP images are ordered as listed and precede URL images, so the first numbered image is primary when present; otherwise the first URL is primary. Duplicate image references are not attached twice. The product cap is 20 total images.

Preview validates product fields and photo matches. With automatic downloads enabled, it validates HTTPS image bytes and shows thumbnails; with the option disabled, remote images are clearly shown as external links and are not fetched. Missing/ambiguous numbered matches and failed downloads return row-specific errors; retrying preview retries URL fetches. Confirmation repeats validation/downloads and writes each product, variants, media references, and initial stock movement transactionally. Active variant stock is summed into parent product stock. The response reports created, skipped, and failed counts; row errors can be downloaded as CSV.

## Upload and hosting limits

This implementation is not a streaming or resumable uploader. The browser can cancel an in-flight request body and retry from the beginning; it cannot resume an interrupted upload. The route calls `formData()`, then buffers the ZIP for parsing. Current limits are 2 MB CSV, 20 MB ZIP, 30 MB expanded ZIP data, at most 2,000 ZIP entries, 5 MB per image, 20 images per product, and a 23 MB combined request. The ZIP parser rejects traversal paths, symlinks, encrypted entries, unsupported compression/types, invalid CRCs, duplicate numbered stems, and excessive expanded size. **1 GB ZIP upload is not supported or verified.** The repository has no hosting configuration proving request-body limits, shared durable staging, disk quota, or multi-instance coordination. Supporting 1 GB safely requires a verified object-storage multipart/resumable upload flow, asynchronous job processing, persistent staging, progress/status APIs, cancellation/retry/cleanup, quotas, and hosting limits that permit it. Do not increase the current in-memory limits to simulate 1 GB support.

Image URL downloads require HTTPS, reject credentials and private/reserved DNS resolutions, manually validate each redirect, enforce declared and streamed size limits, and check response content type against the image file signature. The current deployment must configure a persistent `MEDIA_STORAGE_DIR`; ephemeral serverless local storage is not durable across instances or deploys.
